# M1 + M2 FINAL REPORT — Range Finder Enclosure

## 1. Objective
Build an embedded-vision system that detects a range-finder enclosure using a Raspberry Pi camera, OpenCV and a compact object-detection model.

## 2. Hardware
- Raspberry Pi
- CSI camera
- CSI ribbon cable
- Raspberry Pi OS
- 640×480 camera capture
- Python 3 + OpenCV

## 3. Camera verification
Run:

```bash
rpicam-hello --timeout 5000
python3 01_camera_and_repo/camera_test.py
```

Expected camera test format:

```
CAMERA TEST: PASS
Resolution: 640x480
Channels: 3
```

## 4. OpenCV pipeline
The live pipeline captures a frame, sends it to the detector, draws the detection result, and overlays inference latency and FPS.

```bash
python3 02_opencv_pipeline/main.py --source 0 --weights models/best.pt
```

## 5. Dataset V1
The supplied enclosure photographs were converted into YOLO annotations. The dataset contains 18 labelled images: three source views and five controlled variants per source.

Target class:
`range_finder_enclosure`

YOLO label:
`2 x_center y_center width height`

## 6. Correct split
The split is grouped by source image, so variants of the same original capture do not cross train/validation/test boundaries.

| Split | Images |
|---|---:|
| Train | 6 |
| Validation | 6 |
| Test | 6 |

## 7. Training
Install and train:

```bash
python3 -m pip install ultralytics
yolo detect train model=yolo26n.pt data=dataset/data.yaml epochs=100 imgsz=640 project=runs/detect name=rangefinder
```

Validate on the held-out test set:

```bash
yolo detect val model=runs/detect/rangefinder/weights/best.pt data=dataset/data.yaml split=test
```

## 9. Integrity note
The reference screenshots supplied for this assignment explicitly mark their FPS, latency and confidence as illustrative and state that the mockup is not live inference. Those numbers are therefore not claimed here as real Raspberry Pi measurements.

## 10. Conclusion
The complete software path is implemented: camera capture → OpenCV → object detector → bounding-box overlay → FPS/latency reporting. The remaining numerical M2 fields are generated by the actual Raspberry Pi/model run rather than guessed.
